# A20OS on VirtualBox x86_64

This guide describes how to build and run A20OS with GUI inside **VirtualBox** on x86_64 hosts. QEMU remains the primary development target; VirtualBox is supported as a secondary runtime.

## What is supported today

| Component | Status | Notes |
|-----------|--------|-------|
| Boot (GRUB Multiboot) | Ready | ISO generated by `make vbox-iso-x86_64` |
| Display (GPU) | Ready | VMware SVGA II / VMSVGA driver (`kernel/drivers/gpu/vmsvga.c`) |
| Keyboard/Mouse | Ready | PS/2 controller driver (`kernel/drivers/input/ps2.c`) |
| Disk (SATA) | Ready | Intel AHCI driver (`kernel/drivers/block/ahci.c`) |
| Network | Requires configuration | See network options below |

## Build the ISO

```bash
make vbox-iso-x86_64
```

This produces `.kernel-build/x86_64-qemu-virt-x86_64-both-dev/a20os-x86_64.iso`.

You need `grub-mkrescue` (or `grub2-mkrescue`) on the build host. On Debian/Ubuntu:

```bash
sudo apt-get install grub-common grub-pc-bin xorriso mtools
```

If your build environment does not have GRUB tools, install them first; the ISO cannot be generated without `grub-mkrescue`.

## Create the VirtualBox VM

1. Open VirtualBox Manager and create a new VM.
2. **Type**: `Other` / **Version**: `Other/Unknown (64-bit)` (or `Linux` / `Other Linux 64-bit`).
3. Allocate at least **512 MB** RAM; 1 GB recommended.
4. Add a **SATA** controller and attach an empty raw disk image for now, or use the existing FAT32/ext4 images built by `dev-build` (see Disk section below).
5. In **System → Motherboard → Pointing Device**, select **PS/2 Mouse** (or **USB Tablet**; PS/2 keyboard is still used by the OS).
6. In **Display → Screen**, set:
   - **Graphics Controller**: **VMSVGA** (required).
   - **Video Memory**: at least **16 MB**.
   - **Remote Display**: off.
7. In **Storage**, attach the generated ISO as the optical drive.
8. In **Network**, choose one of the supported adapters (see Network section below).
9. Start the VM. It should boot from the ISO, show the GRUB menu, and load the A20OS kernel with the GUI logo.

## Display

VirtualBox exposes the **VMware SVGA II** adapter as **VMSVGA**. A20OS includes a native driver for PCI ID `0x15AD:0x0405` that:

- Negotiates the SVGA II protocol (`SVGA_ID_2`).
- Sets a 1024×768×32 frame buffer.
- Registers the device as the default `/dev/fb0` source.

If you see no video output, make sure the VM is configured with **VMSVGA** (not VBoxVGA or VBoxSVGA) and that the guest additions are **not** installed — they are not needed for a bare-metal kernel.

## Input

VirtualBox routes the keyboard through the emulated **PS/2 controller** by default. A20OS initializes the PS/2 controller (ports `0x60`/`0x64`) and supports:

- PS/2 keyboard (set 1 scancodes with translation).
- PS/2 mouse (relative motion, left/right/middle buttons).

Both feed input events through `/dev/input0` using the same `struct input_event` ABI as the virtio-input driver.

## Storage

A20OS now includes an **AHCI/SATA** driver (`kernel/drivers/block/ahci.c`) that probes PCI AHCI controllers (common Intel IDs such as `0x8086:0x2922` and `0x8086:0x2829`). This is the controller VirtualBox uses for its default SATA disk.

To boot with a usable `/bin` filesystem, configure the VM as follows:

1. In **Storage**, add a **SATA** controller.
2. Create or attach a raw disk image. The `dev-build` target already produces FAT32 and ext4 images; for first tests you can convert the FAT32 image to a virtual disk with `VBoxManage convertfromraw` or attach it as a raw `hdd` medium.
3. Start the VM. The kernel ISO boots, the AHCI driver should detect the disk, and `mount_block_devices()` will try to mount `/bin` and `/test` from it.

### Preparing a disk image for testing

The `dev-build` target creates `.kernel-build/x86_64-qemu-virt-x86_64-both-dev/fat32.img` and `.kernel-build/x86_64-qemu-virt-x86_64-both-dev/ext4.img`. Convert the FAT32 image to a VDI and attach it:

```bash
VBoxManage convertfromraw .kernel-build/x86_64-qemu-virt-x86_64-both-dev/fat32.img a20os-fat32.vdi --format VDI
VBoxManage storageattach "A20OS" --storagectl "SATA" --port 0 --device 0 \
    --type hdd --medium a20os-fat32.vdi
```

Alternatively, attach the raw image directly if VirtualBox allows it on your platform:

```bash
VBoxManage storageattach "A20OS" --storagectl "SATA" --port 0 --device 0 \
    --type hdd --medium .kernel-build/x86_64-qemu-virt-x86_64-both-dev/fat32.img
```

> Note: the AHCI driver only supports 512-byte sectors and LBA48 ATA commands. It is sufficient for FAT32/ext2/ext4 testing but has not been validated with optical drives or ATAPI devices.

## Network options

A20OS currently has a **virtio-net** driver. VirtualBox supports:

- **Intel PRO/1000 MT Desktop** (E1000) — not yet supported by A20OS.
- **VirtIO** network adapter — available in VirtualBox as an option.

To use networking, set the VM network adapter to **VirtIO**:

1. Settings → Network → Adapter 1 → **Advanced** → **Adapter Type**: **VirtIO**.

If the VirtIO adapter is not available, networking will not function until an E1000 driver is added.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `grub-mkrescue not found` | Missing GRUB build tools | `apt install grub-common grub-pc-bin` |
| Black screen after GRUB | Wrong graphics controller | Set Display → VMSVGA |
| No keyboard input | USB tablet or no PS/2 | Use PS/2 keyboard/mouse |
| `Cannot open /bin/init` | AHCI disk not detected or wrong controller | Confirm SATA controller + AHCI driver messages; check disk image format |
| SeaBIOS / iPXE "Booting from ROM" with no A20OS | QEMU booted the network ROM because the kernel was not loaded; usually stale or missing `kernel.elf`, or a different `run-*` target was used | Run `make run-gui-x86_64` (not `run-x86_64`); check that the printed `kernel.elf` path exists and is non-empty; run `make clean` then rebuild |
| No network | Wrong adapter type | Select VirtIO network adapter |

## Files involved

- `kernel/drivers/gpu/vmsvga.c` — VMSVGA GPU driver.
- `kernel/drivers/input/ps2.c` — PS/2 keyboard/mouse driver.
- `kernel/drivers/block/ahci.c` — Intel AHCI/SATA driver for the VirtualBox SATA disk.
- `kernel/drivers/gpu/framebuffer.c` — generic framebuffer ABI (`/dev/fb0`).
- `kernel/drivers/gpu/gpu_core.c` — default GPU device registry.
- `kernel/main.c` — tries AHCI (`ahci_get_dev(0)`) after virtio-blk when mounting `/bin` and `/test`.
- `scripts/mk_grub_iso.sh` — ISO generator.
- `Makefile` — `vbox-iso-x86_64` target.
- `kernel/arch/x86_64/boot/entry.S` — Multiboot v1 header.
