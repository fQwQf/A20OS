## Per-workload result

`acquires` / `spins` / `max_spins` are the workload window only: the counters are zeroed with `echo reset > /proc/a20/lock_contention` immediately before the workload command and read immediately after, so boot-time traffic is excluded by construction rather than subtracted after the fact. `Control-window` is the same counters between the reset and the first read -- the floor the workload numbers sit on.

**Noise discipline.** `docs/server-readiness.md` records repeated runs of one 4-core workload spanning 0 to ~920024 spins, and this table's own max-min spread is the honest resolution limit for every cell below. A post-change median that differs from the baseline median by less than that cell's max-min spread is **not resolvable** at this sample size and must be written as such rather than claimed.

## Reproducing

The measured guest kernel is the ABI=linux NR_CPUS=8 dev variant, the same build directory docs/roadmap/perf-overhaul.md §5 names and the one smoke-smp-lock-contention boots at NR_CPUS=4. The plain release build is the unmodified-kernel build check; its `instances/release-riscv64.toml` also pins smp=8.

```sh
# 1. unmodified kernel builds clean (both arches); -> kernel-rv, disk.img
make -s ARCH=riscv64 BOARD=qemu-virt-riscv64

# 2. the measured image: 8 vCPUs, ABI=linux dev variant
make -s ARCH=riscv64 BOARD=qemu-virt-riscv64 ABI=linux BRINGUP=0 \
     NR_CPUS=8 dev-build

# 3. the measurement itself
RUNS=5 SMP=8 WORKLOADS=mm_stress,net_stress,sched_stress,futex_stress \
  OUT_DIR=/home/fqwqf/OS/A20OS-locks/docs/measured tools/lock_bench.py --phase baseline

# or, equivalently, through make (same harness, same defaults):
make bench-locks RUNS=5 SMP=8 PHASE=baseline
```

The post-modification round is the same command with `--phase after` and `OUT_DIR=docs/measured`, so no file in this directory needs editing to re-measure. Per-run console logs land in `.kernel-build/bench-logs/<phase>/<workload>/run<N>/console.log` and are not committed; the JSON carries the parsed snapshots.
