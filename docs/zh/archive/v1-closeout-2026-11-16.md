## AArch64 服务恢复

修复了三类实际问题：

1. RTC 服务原来使用 RISC-V Goldfish 地址。AArch64 现使用固件枚举的 PL031 页 `0x09010000` 和 GIC INTID 34，C/Rust 服务共享寄存器协议，映射授权限制在该页。PL031 只有整秒精度；100 ms 闹钟请求保守取整，本轮约 2 s 后经真实 IRQ 回答。
2. 原生监督程序没有消费 SIGCHLD 的 libc 检查点。现在用线程信号掩码屏蔽该通知，以 EXITED 事件跟踪子服务。测试清理原来调用 signal 0，仅检查存活；现改为 SIGKILL 并等待真实退出。Native EXITED 的 `-9` 与 TASK_WAIT 的 shell 状态 137 予以区分。
3. Native 目录创建和 mount tree 变更未应用 chroot 根目录。目录创建、挂载、卸载和文件服务注册现共用 dirfd/chroot 解析器；生产 C 系统调用、实际共享解析器与 Rust 路径算法组成的 host 测试覆盖根目录、相对路径、目录句柄和越界拒绝，未应用根目录的负控失败。

开发镜像的公开入口为 `tools/probes/aarch64_supervision_probe.py`。C/Rust 各完成独立 echo 恢复、两次 RTC 恢复和三轮监督恢复，正常关机审计为 0，独立服务 FAT 检查通过。

桌面入口为 `tools/probes/aarch64_desktop_supervision_probe.py`，测试服务和脚本一并保存在 `tools/probes/desktop_supervision.openrc`、`tools/probes/desktop_supervision_guest.sh`。它复制输入磁盘，再注入测试和指定的 Native 二进制；未修改输入 world 或 FAT。典型调用：

```sh

  --kernel <SMP4-kernel.bin> --fat <development-fat32.img> \
  --world <xfce-aarch64.img> --user-build-dir <matching-native-binaries> \
  --output <private-evidence-directory>
```

实际桌面使用四个 vCPU、2 GiB QEMU 内存、virtio GPU/输入设备，以及 `packages/world/xfce.world` / `packages/overlay/xfce` 组成的 Alpine/OpenRC world。labwc 和 xfce4-panel 运行期间，C/Rust 两套监督程序分别完成三轮 HANG、健康超时、SIGKILL、重绑、旧端点失效和越权终止拒绝；UFSD 使用第三块独立 FAT，完成文件写入/读回、删除和卸载。随后正常关机，审计 0，实际写过的桌面盘 e2fsck 和服务盘 fsck.fat 均退出 0。此处没有认证键盘/按钮交互或完整桌面体验。

## UFSD 服务死亡与重挂载

实现提交 `cde083a50`、`2e3b685aa`。真实 SIGKILL 最初使旧 fd 的 GETATTR 等到 errno 110，随后系统因死服务拒绝关机。C 通道桥现在在发送与每次等待回复时检查服务任务死亡；挂载持有的 proc 引用保证该状态可读。Rust close 控制器在死亡证明成立后退休本地 fctx，保留原 EIO；VFS 消费 fd 并释放本地挂载所有权，不伪造 CLOSE/CONFIRM ACK。活服务 I/O 错误的重试/失败关闭保持不变。

三轮恢复通过后，加长到八轮发现第九次挂载失败：static UXFS 只有八槽，根 vnode 和缓存页的旧引用使槽一直不能复用。修复将 factory root 引用转移给 mount 一次，成功卸载时以一次性标记交还；外部子对象/open/mapping 引用继续保护旧 root/sb，最后 release 才撤销墓地 mount 的根指针。解绑先撤销旧服务的块权限，再清除退休身份的非固定缓存页，避免缓存把父 vnode/sb 永久保留；inode 号码复用时只失效旧身份的干净缓存，保留活服务的脏页。

公开入口：`tools/fs/ext4_orphan_lifecycle_gate.py --service-death --cycles 8`，用 `--test` 指定 `ufs_orphan_recovery_test` 并以 `--ufsd` 选择同构建的控制器。每轮校验独立卷 token、持久化文件和 orphan、SIGKILL/回收真实服务、旧 fd GETATTR EIO、关闭 EIO 且槽已成为 EBADF、卸载和新服务挂载、已链接文件内容不变、新文件可持久化，最后正常卸载和关机。
