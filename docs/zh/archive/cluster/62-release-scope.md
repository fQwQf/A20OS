# 1.0 集群语义范围决定

> 本文是范围决定，不是实现进度记录。当前行为见[cluster-implementation-status.md](../../../archive/status/current/cluster-implementation-status.md)。

## 已承诺的语义

CA/1 与 CA/2 是 1.0 交付的两种应用生命周期接口，二者共享同一个 app owner：

- 一个启动由 `(controller object_id, client object_id, nonce)` 定位；CA/2 再加上 owner 分配的 slot token。
- 同一个键的重复 START 返回原来的根任务和状态，不会再次装载或执行。
- START 回复丢失或传输超时表示**结果未知**。调用者只能对原 ticket 做 resume/query，或在同一个 controller 上显式重试同一个键；不会换一个执行域再启动一次。
- owner 进程死亡会改变 controller 任务身份，旧 ticket 返回 `EXPIRED`；原应用由 `PARENT_BOUND` 规则终止，新 owner 不会从旧 ticket 恢复执行。
- 内核重启使原 boot epoch 失效，旧 ticket 与旧对象名都不能解析到新启动中的同序号任务。
- 对象目录的记录在所属域内带租约；查询、续租、撤回和重发布在目录进程生命周期内有效。目录或内核重启后，由存活发布者显式重新发布，不自动重放。

这些保证覆盖**当前 owner、当前会话和当前启动**。它们是“至多一次可见执行”加结果保留/查询，不是跨重启的持久 exactly-once。

## 明确排除的范围

以下能力不属于 1.0，也不以“部分实现”的形式保留在缺口台账中：

1. **跨重启 exactly-once。** 没有持久事务日志、稳定存储的启动记录或共识协议。owner 或内核重启后，旧请求既不重放也不去重；调用者得到 `EXPIRED`，必须自行定义业务幂等键。关闭或重开连接、重新获取 offer/token 都表示一次新的执行。
2. **运行中进程的自动迁移。** 应用只在启动时按活动程序数选择执行域；运行后不会被调度器、成员故障或负载变化搬到另一域。同一 Native 线程的栈、PC 与句柄仍受 ISA/ABI 和执行域约束。故障恢复的语义是“不重复执行 + 明确失效”，不是“在别处继续运行”。
3. **controller 故障后的自动接管。** 没有从旧 controller 到新 controller 的持久票据转交。管理员可以重新部署并启动新应用，但这是新的执行，不是原 ticket 的恢复。
4. **全局强一致目录枚举。** 对象目录是按所属域分片的查询服务；`NOT_FOUND`、不可达和租约到期不互相推断，也不提供跨域原子快照。

## 为什么不在 1.0 实现

- 跨重启 exactly-once 需要持久提交记录（或共识）来决定“已执行/未执行”，而当前 MCU 与服务器共用的是有界内存状态机；把这一层塞进 1.0 会改变存储、恢复和权限模型，且没有可复现的物理多板依据。
- 自动迁移需要同 ISA/ABI 的可迁移执行状态、内存与句柄的所有权转移、设备 fencing 和失败回滚。现有共享 RAM 原型只证明同一内核内的 CPU 迁移，不是独立域之间的在线迁移。
- 持久启动记录会引入“重放旧请求”的攻击面。本轮选择在启动代次、controller 身份和传输代次上失败关闭（`EXPIRED`），而不是猜测旧结果。

这些是设计边界，不是待办项。若未来成为研究或产品需求，应新增独立工作包，携带持久存储、故障矩阵和物理部署证据，而不是修改本文的 1.0 承诺。

## 与故障恢复的关系

1.0 的故障恢复契约是：

| 故障 | 可观察结果 | 不发生的事 |
|---|---|---|
| START 回复丢失 | 超时；原 ticket 可查询到 RUNNING 或原状态 | 换域重试、二次装载 |
| owner 进程死亡 | 旧 ticket `EXPIRED`；应用按父死亡规则终止 | 新 owner 自动重放旧键 |
| 网络分区 | 调用超时；恢复后原 ticket 仍指向同一 controller/root | 把不可达当成 RETIRED/EXITED |
| 成员在启动前不可达 | 候选被跳过，存活 owner 执行一次 | 在多个域同时执行 |
| 内核重启 | 旧对象名/ticket `EXPIRED`；发布者需重新发布 | 跨启动复用身份或自动恢复 |

对应的真实 ELF 故障用例见[37](37-application-execution.md)、[39](39-application-recycling.md) 与[36](36-object-directory.md) 的验收小节。
