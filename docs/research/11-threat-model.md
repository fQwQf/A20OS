# 威胁模型与攻击测试

> **本文定义系统面对的攻击者、防御映射与攻击面量化**（重组自旧创新分析文档 §9，并新增**信封逃逸**这一主会核心攻击维度）。核心：让"预算能力 + 类型化通道 + 能力信封"的安全主张可以逐条对照攻击者验证，而不是空泛的"更安全"。攻击套件规格与 10-evaluation §E7 对接。

---

## 1. 攻击者层级

| 层级 | 攻击者能力 | 代表场景 | 我们承诺的防线 |
|------|----------|---------|--------------|
| $\mathcal{A}_0$ | 无特殊能力 | 正常用户 | 无（系统正常可用） |
| $\mathcal{A}_1$ | 控制一个用户态进程 | 应用/库漏洞利用、**被攻破的包脚本/插件** | 权限单调、预算过期、类型过滤、**信封边界** |
| $\mathcal{A}_2$ | 控制多个协作进程 | 多进程协同攻击 | confused deputy 静态消除、委托耗散 |
| $\mathcal{A}_3$ | 控制一个 Linux ABI 进程（信封外） | 跨 ABI 攻击 | 能力边界（05 §5，$BridgeFree$） |
| $\mathcal{A}_4$ | 共享资源侧信道 | Spectre/Meltdown 类 | **不承诺**（承认残余隐信道，06 §8.5.4） |
| $\mathcal{A}_5$ | 利用内核 bug | 内核漏洞利用 | **不承诺**（依赖内核正确性；08 机器检验降低风险） |

**诚实边界**：信封附加**能力预算**，不解决被攻破进程的内部行为（ROP、内存破坏）。$\mathcal{A}_4$、$\mathcal{A}_5$ 不在承诺范围。**信封不是"完整安全沙箱"，是"资源获取的能力预算"**——论文必须这样写。

## 3. 攻击面量化

$$AS(S) = \sum_{p \in P} \sum_{h \in HT_p} |\rho_{eff}(h, t)| \times \frac{1}{1 + \text{constraint\_depth}(h)}$$

| 配置 | 约束深度 | 攻击面 | 缩减率 |
|------|---------|-------|-------|
| 基础 handle | 0 | $|\rho| \times H$ | 0% |
| + 权限降级 | 1 | $|\rho'| \times H$ | ~30-50% |
| + 预算约束 | 2 | $|\rho'| \times H \times \frac{\Delta t}{T}$ | ~60-90% |
| + 类型化通道 | 3 | $|\rho'| \times H' \times \frac{\Delta t}{T}$ | ~80-99% |

**注意**：这是理论模型。E2（供应链场景）必须以真实攻击尝试给出**实测**的失败/成功数据，而不是只报这个理论表。

## 4. 攻击测试套件规格（对应 10-evaluation §E7）

### 4.1 权限与能力攻击（A 系列）

| 编号 | 尝试 | 预期 |
|------|------|------|
| A1 | dup 请求超集权限 | ACCESS |
| A2 | 无 READ 权读 | ACCESS |
| A3 | 无 TRANSFER 权经 channel 传 handle | ACCESS |
| A4 | recv 收到的 handle 权限 > 发送方授予 | 不可发生（内核强制） |
| A5 | spawn 注入超父进程权限的 handle | ACCESS |
| A6 | close 后使用 | BAD_HANDLE |
| A7 | vm_map 无 MAP 权 | ACCESS |
| A8 | 伪造用户态 handle 值 | BAD_HANDLE |

### 4.2 预算能力攻击（T 系列）

| 编号 | 尝试 | 预期 |
|------|------|------|
| T1 | dup/transfer 刷新 expiry 或增加 ops | 拒绝（不可刷新，03 定理 3.2） |
| T2 | 过期后继续操作（含 re-install 读） | ACCESS（03 定理 3.1） |
| T3 | 并发 sweeper vs 操作竞态（验证无既成功又过期的窗口） | 无交叉状态（03 定理 3.3） |
| T4 | 边沿：expiry 精确等于当前 tick | 语义一致（< vs ≤ 明确） |
| T5 | OP_COUNT 耗尽后操作 | ACCESS |

### 4.3 类型化通道攻击（P 系列 = Propagation，避免与贡献 C1-C4 撞名）

| 编号 | 尝试 | 预期 |
|------|------|------|
| P1 | 发未声明类型的 handle | TYPE_MISMATCH（04 定理 2.1） |
| P2 | 超 max_data_size / max_handles | 拒绝 |
| P3 | recv 端类型不符 | TYPE_MISMATCH |
| P4 | 经用户态修改类型字段绕过 | 无效（内核端点只读拷贝，04 §2.2） |
| P5 | confused deputy：入通道类型 ∩ 出通道类型 ≠ ∅ 时尝试传 handle | 依赖配置；验证 04 定理 8.3 判定规则 |

### 4.4 跨 ABI 攻击（D 系列）

| 编号 | 尝试 | 预期 |
|------|------|------|
| D1 | Linux 进程经共享文件注入，试图影响 Native 通道类型约束 | 无效（类型签名在内核空间只读，04 §2.2；降级通道只传内容，05 定理 1.2） |
| D2 | Linux 进程经 fd 读 Native 写过的文件，尝试推断 handle rights | 无权限元数据（05 推论 1.2.1） |

### 4.5 供应链场景（对应 10 §E2）

完整攻击注入：被攻破的包脚本/插件尝试 (a) 访问文件系统 (b) 传回 task/shm handle (c) 超时后继续 (d) dup 刷新。全部应失败；对照（无信封/仅 seccomp/仅 Landlock）配置下应成功——用对照说明机制价值。

### 4.6 信封逃逸攻击（EN 系列，主会核心）

**目的**：攻击"全获取咽喉"主张。每一类逃逸路径都要在论文里正面回应——覆盖的写清机制，不覆盖的写进 threat model。

| 编号 | 逃逸尝试 | 预期 | 防线/回应 |
|------|---------|------|----------|
| EN1 | 调用**未被调解**的资源 syscall | 无（所有资源 syscall 已枚举进 Mediated） | 咽喉完备性清单（08 模块 4） |
| EN2 | 经 procfs/sysfs 走私资源（`/proc/self/fd`、打开 `mem`） | 拒绝或受预算约束 | procfs 访问也须过调解；`/proc` 能力分析 |
| EN3 | 继承未入账的 fd（fork/exec 时 fd 表复制） | 子进程继承信封且预算耗散；fd 入账 | 继承协议（05 §2.3） |
| EN4 | 用 `mmap(MAP_SHARED)` 共享内存走私能力 | 共享映射受信封类型/权限约束 | 影子 handle 覆盖 mmap |
| EN5 | 经 socketpair/AF_UNIX 传给信封外进程能力 | 传播维度拒绝（propagation ⊆ policy） | typed 传播约束（04） |
| EN6 | `execve` 换身份 / setuid 提权 | exec 复查 policy；拒绝身份逃逸 | exec 复查（05 §2.2） |

**对照攻击**：同一攻击集在 仅seccomp / 仅Landlock / 无信封 下表现——证明对象能力预算相比 syscall/路径级过滤的差异。
