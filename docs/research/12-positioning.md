## 1. 一句话定位

> **A20OS 提出"能力信封"：在一个双 ABI 能力内核中，把预算能力（类型 × 权限 × 时间 × 次数 × 传播的内核强制授权，单调衰减、不可刷新、过期原子）以零源码改动的方式施加到未修改的 Linux 二进制上——把能力系统从"重写命令"变成"部署选项"，并以可证明、可测量的方式在包安装/插件/供应键场景中验证。**

核心洞察（论文的 "aha"）：**预算可部署，权限不可部署**——二元权限要求代码重写，量化且可耗竭的预算可以在部署时注入。

## 3. 论文叙事（问题-差距-洞察-方法-结果）

**问题**：能力系统四十年来未被采纳——重写命令 + 授予即永久；而供应键/插件/包安装的真实威胁恰恰需要"临时、受限、可回收的能力"。

**差距**：Capsicum 需源码改动、无时间维度；Landlock/seccomp 无对象模型、无预算；gVisor/starnix 无能力对象模型、用户态开销；seL4/Zircon 全重写、无遗留二进制。**没有任何系统能对未修改二进制施加"类型+权限+时间+次数"的对象级能力预算。**

**洞察**：
1. 预算是量化的、可耗竭的、可注入的——权限不是。
2. 双 ABI 内核是资源获取的唯一咽喉 → 可以透明调解一切资源获取。
3. 混合信任边界保证信封进程无法走私进 Native 空间（双向边界）。
4. 单调采用使渐进部署无风险。

**方法**：
1. 预算能力模型 + 形式化（03/06）。
2. 信封调解器（全获取咽喉 + 影子 handle + 继承耗散）（05）。
3. 机器检验核心（08）。
4. 包安装/插件场景评估 + 攻击套件（10/11）。

**结果**：一个运行未修改 musl/Linux 二进制的双 ABI 内核 + 预算能力机制（时间/次数维度已实现）+ 信封调解器（实现中）+ 机器检验核心（计划）。

## 4. 为什么这能冲主会（对 OSDI 标准的压力测试）

| OSDI 标准 | 满足度 | 条件 |
|---|---|---|
| 可测量的系统贡献 | 强：信封调解是全内核机制，评估可量化 | 执行（W2/W3） |
| 真实问题牵引 | 强：包安装/插件/供应键是头号产业痛点 | 已成立 |
| 新颖性扛得住 | 中-强：信封调解器是全新机制；预算建模需 vs leasing/SPKI/OAuth 精确区分 | 09 检索（W1） |
| 机器检验 | 中：TLA+ + Lean 覆盖能力核心（本代码库规模可行） | 执行（W4） |
| "为什么非你不可" | 强：双 ABI + 对象模型 + 预算 + 全局咽喉三件套，Linux/微内核都不具备 | 已成立 |

**最可能被攻击的点**（提前自攻）：
1. "预算不新鲜（leasing/SPKI）" → 反驳：内核强制 + 多维预算格 + 单调衰减/不可刷新形式化 + 双 ABI 载体；leasing 是分布式缓存一致性，SPKI 是用户态证书。
2. "为何不做在 Linux 上" → 反驳：Linux 无对象能力模型、无法按进程施加时间/次数/类型预算；在 Linux 上要达成需大量 LSM/hook 且无形式化。
3. "信封 = 换个马甲的 seccomp" → 反驳：seccomp 按 syscall 号过滤（无对象、无预算、可被白名单绕过），信封按对象能力 + 预算（无法通过获取方式绕过）。
4. "评估是不是挑数据" → 反驳：攻击套件全覆盖 + 开销如实报告 + 与 Capsicum/Landlock/seccomp 同一攻击集对照。
