# A20OS 1.0 first-wave progress ledger

Snapshot date: 2026-10-13. This is a first-wave status view of the twelve
stable V1 work-package IDs. It is **not** the complete requirements ledger:
the TODO/design/source audit required by [the 1.0 plan](v1.0.md) remains open,
and unlisted work must not be treated as cancelled. None of the packages is
closed. A smoke gate, source implementation, release tag, or this ledger does
not substitute for the required functional and performance evidence.

The fixed C0 baseline is not yet certified. The `v0.18` tag is an available
revision identity, not evidence that the complete C0 workload, platform, and
performance matrix passed. The paired runner and protocol are described in
[the comparison protocol](v1.0-comparison.md); the 1.0 validation plan remains
the authority for full acceptance.

The first machine-audited source inventory is available at
[`v1.0-requirements.json`](v1.0-requirements.json), generated and checked with
`python3 tools/v1_requirements.py --write` and `--check`. The snapshot hashes
all scanned project text inputs, separates source-entry candidates from
manually triaged requirements, and records exclusions as third-party,
generated, historical, retired-platform, research-not-committed, or inventory
tooling. The first ten requirements are the priority delivery queue; one
cross-cutting hardware-compatibility constraint is also manually recorded.
All other active candidates remain `needs_triage`. This is a first inventory pass, not a claim
that every candidate has been reviewed. The scanner records checklist and
known-issue queue entries as well as source phrases, and does not decide scope
from keywords alone. Per-file content hashes are retained as a timestamped
snapshot for audit; `--check` tracks the source catalog, extracted candidate
text, and manual anchors, so an unrelated code edit does not make prose drift
fail. Regenerate and review the inventory when a candidate entry or its source
anchor changes.
