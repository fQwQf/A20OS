# A20OS 1.0 paired comparison protocol

This protocol and `tools/v1_compare.py` provide a small G0 evidence runner. They
do not establish a C0 baseline, certify the current `v0.18` tag, or claim that
any subsystem or platform has passed. The initial NET slice is intended to
compare the C and Rust `netfilter_rewrite` implementations using the same
packet fixtures and guest workload. Host oracle results establish local
functional behavior; only guest results exercise the kernel data path, and a
NAT microbenchmark alone cannot establish whole-system non-regression.

## Identities and inputs

Every protocol file records three explicit identities: fixed C0, most recently
validated Cn, and candidate. Each identity includes an id, revision, a
`validated` boolean, and a traceable evidence reference. A tag or a successful
build is not validation. A result may be collected while a baseline is still
unvalidated, but its status remains `EVIDENCE_INSUFFICIENT` until C0 and Cn
have evidence and are marked validated.

The protocol also records one SHA-256 for the exact shared inputs and an
environment table. The same case, workload arguments, fixtures, guest
configuration, and measurement units must be used for each identity. Only the
implementation selector and the build inputs that necessarily identify the
implementation may differ. Keep large images outside the evidence directory;
record their hashes and use separate writable overlays or snapshots for every
invocation. The runner creates separate run directories, but it is not a
sandbox: configured commands can write anywhere their host account permits.
Use trusted commands and configure them to isolate mutable images and state.

The runner accepts argv arrays and does not invoke a shell. It provides
`A20_COMPARE_RUN_DIR`, `A20_COMPARE_CASE`, `A20_COMPARE_ITERATION`, and
`A20_COMPARE_VERSION` to each command. The command must emit exactly one line
of this form on stdout or stderr:

```text
A20_COMPARE_JSON: {"schema":1,"case":"nat-rewrite/csum","contract":{"input_sha256":"…","output_sha256":"…","errors":0},"metrics":{"packet_ns":123.4}}
```

`contract` is compared as exact JSON data against `expected_contract`, which
must be specified independently in the protocol. This prevents C and Rust
implementations from passing by agreeing on the same wrong answer. All metric
names declared for a case must be emitted exactly once in the result object;
values must be finite positive numbers. A functional-only result uses an empty
`metrics` object. Add a metric's direction, unit, and any actual hardware or
resource limit to the protocol before running the candidate. For a hard maximum
use `budget_max` on a lower-is-better metric; for a hard minimum use
`budget_min` on a higher-is-better metric.

Each performance metric also pins `calibration_sha256`,
`calibration_evidence`, `resolution_ratio`, and
`noninferiority_bound_ratio`. The calibration hash identifies a separately
collected, reviewed baseline self-control dataset. The non-inferiority bound
must equal that fixed resolution ratio. The runner never derives or enlarges
the bound from candidate-era measurements. Current repeated C0/Cn self-controls
are only a quality check: if their measured 95% upper interval exceeds the
pre-registered resolution, the result is evidence-insufficient. A noisy run
cannot grant itself a wider tolerance.

Example shape (commands are deliberately placeholders; a real protocol must
pin identities, fixtures, commands, and environment before execution):

```toml
schema_version = 1

[comparison]
id = "V1-NET-rewrite"
requirement_id = "V1-NET"
protocol_id = "nat-rewrite-v1"
inputs_sha256 = "<64 hex digits for immutable fixtures and shared config>"
order_seed = 71
environment = { host = "Linux", guest = "riscv64 QEMU", toolchain = "record exact versions" }

[versions.c0]
id = "fixed-c0"
revision = "<commit and patch identity>"
validated = false
evidence = "pending: C0 functional and performance validation"

[versions.cn]
id = "last-accepted-c"
revision = "<commit and patch identity>"
validated = false
evidence = "pending: Cn acceptance record"

[versions.candidate]
id = "rust-netfilter-rewrite"
revision = "<candidate commit and patch identity>"
validated = false
evidence = "candidate under test"

[[cases]]
id = "nat-rewrite/csum"
kind = "functional_performance"
repetitions = 6
timeout_seconds = 120
expected_contract = { input_sha256 = "<fixture digest>", output_sha256 = "<oracle digest>", errors = 0 }

[cases.metrics.packet_ns]
direction = "lower"
unit = "ns/packet"
calibration_sha256 = "<64 hex digits for reviewed baseline self-control data>"
calibration_evidence = "<retained calibration record>"
resolution_ratio = 1.0
noninferiority_bound_ratio = 1.0

[cases.commands.c0]
argv = ["<trusted adapter>", "--impl", "c"]
artifact_paths = ["<kernel or test binary produced/used by this run>"]
cwd = "."
env = { }

[cases.commands.cn]
argv = ["<trusted adapter>", "--impl", "c"]
artifact_paths = ["<kernel or test binary produced/used by this run>"]
cwd = "."
env = { }

[cases.commands.candidate]
argv = ["<trusted adapter>", "--impl", "rust"]
artifact_paths = ["<kernel or test binary produced/used by this run>"]
cwd = "."
env = { }
```

## Repetitions and status rules

For each repetition, the runner executes C0 twice, Cn twice, and the candidate
once. It shuffles their order with the pre-registered `comparison.order_seed`
and gives each process a fresh directory. The observed schedule is retained in
the report. The two baseline runs check self-control noise against the
independently calibrated fixed resolution. At least six repetitions are
required for performance cases. The runner calculates an exact,
distribution-free order-statistic confidence interval for the median. If the
number of observations cannot support a 95% interval, it reports
`EVIDENCE_INSUFFICIENT`. It does not assume a 5% or 10% tolerance: the
pre-registered resolution comes from independent baseline calibration, not a
chosen default and not the candidate run. A metric passes only when the
candidate's upper degradation-ratio interval is within that fixed resolution.
A confirmed excess is `FAIL`; overlapping intervals or noisy controls are
`EVIDENCE_INSUFFICIENT` and require better measurement or more repetitions.

Each command's full stdout, stderr, argv, working directory, exit status,
elapsed time, timeout state, marker, and fatal-text audit are written under its
run directory. The report includes stdout/stderr hashes, actual argv and
configured-environment hashes, built/tested artifact hashes, the host runtime,
and a copy/hash of the exact protocol file. A command timeout terminates its
process group, including remaining descendants after the grace period. Panic/fatal
matches, a nonzero exit, a missing/duplicate/malformed result marker, contract
mismatch, missing metrics, and hard-budget violations fail that run. Failed
rounds remain in the report and are never silently excluded from a passing
aggregate. The evidence output directory must not already exist, so a rerun
cannot overwrite prior failures.

The aggregate is `PASS` only when all cases pass and both C0 and Cn are marked
validated. Missing execution, an unvalidated baseline, too few observations,
or a confidence interval obscured by noise is `EVIDENCE_INSUFFICIENT`. This
first runner only handles declared cases and metrics. It does not close the
broader V1 work packages, certify every ISA or board, or replace the full
feature/performance matrices in [v1.0 validation](v1.0-validation.md).

Run the hermetic runner checks with:

```sh
python3 -m unittest tools.tests.test_v1_compare
```

Run a real protocol with:

```sh
python3 tools/v1_compare.py docs/releases/<protocol>.toml --out <new-evidence-directory>
```

Keep source revisions, fixture and artifact hashes, raw logs, and the generated
`report.json` together in the project's retained evidence store. Do not commit
large disk images or credentials into the repository.
