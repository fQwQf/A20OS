# 子系统实现与验证状态（2026-10-19）

This is a scoped status of the seven integrated module branches, not a declaration that the OS or 1.0 acceptance is complete. Source integration and a focused passing test do not close a module's full functional or platform goal.

| Area | Integrated behavior | Evidence and remaining limits |
| --- | --- | --- |
| Signal | Rust signal core with Linux/Native signal and signalfd wiring. | Three guest smokes passed. Three paired C/R measurements are small samples with overlapping ranges; they do not establish a stable performance advantage. See [Signal evidence](evidence/signal/current-2026-10-19/README.md). |
| ELF / exec | Rust ELF planning and exec/kexec transaction paths are integrated. | RV64 and AArch64 focused guest cases plus host fixture replay are available in [the ELF manifest](evidence/elf-exec/manifest.md). Kexec handoff remains unavailable on the tested QEMU path; NOMMU checks are object builds, not guest validation. |
| Filesystem | Rust owns selected complex VFS, UXFS, procfs and cache state transitions; C fast paths remain where appropriate. | A focused cache comparison found no stable rename/unlink regression in the final same-profile samples. ISOFS pressure coverage is incomplete; NTFS crash/remount fails on both implementations; ext4 no-journal deferred-orphan EIO remains unresolved. See [FS evidence](evidence/kernel-integration/fs-cache-final-2026-10-19.txt) and [consistency limits](../fs/fs-consistency-model.md). |
| Linux and Native IPC | Rust owns accepted MQ, SysV, Landlock/seccomp, Native IPC and wait/fault transaction slices. | The combined RV64 ABI-both SMP2 guest ran three focused programs and exited naturally with status 0. This is not coverage of every IPC operation/profile. UFFD's old C race control failed while the Rust path passed; performance samples remain noisy. See [combined IPC run](evidence/kernel-integration/ipc-combined-2026-10-19/README.md), [futex/UFFD race and performance evidence](evidence/kernel-integration/futex-uffd-2026-10-19.md), and [Native IPC comparisons](evidence/native-ipc/README.md). |
| MM-VM | Rust transaction slices cover VMA/VMO/COW, fork, reclaim, shared-write shutdown and fault handling. | Twelve focused smokes passed on the recorded tree. The evidence archive lacks per-run kernel/FAT/user hashes and argv for some runs; no cross-architecture runtime conclusion follows. See [MM evidence](evidence/kernel-integration/mm-final-2026-10-19/README.md) and [MM contract](../mm-fork-mprotect-cow.md). |
| Process | Rust owns selected task construction, ordered exit, wait/timer and scheduling decisions; task storage, PID allocation and some final release remain C/configurable. | Existing host and SMP2 evidence is focused. `TASK_OBJECTS_IMPL` and `TASK_EXIT_IMPL` default to C; the ordered exit controller is wired separately. See [process lifecycle and scheduling](../process-scheduler.md). |
| Network | Rust owns selected socket queue and connection state transactions. | One RV64 SMP2 run completed 4 parallel transfers × 4 rounds × 1 MiB and exited 0. The evidence is from a mixed build and does not close full `network_suite`, external peer/NAT, or performance acceptance. See [stress evidence](evidence/kernel-integration/network-stress-candidate-2026-10-19/README.md) and [poll evidence](evidence/kernel-integration/network-poll-final-2026-10-19/README.md). |

The 2026-10-19 ordinary `tools/a20 run qemu-riscv64` shell gate reached the shell and powered off naturally. It used a tree with 26 tracked and 12 untracked changes, so it is not a clean release-candidate result. The related `check-a20-tests` run reported 6 failures, 36 errors and 1 skip among 476 tests; it was not rerun against a clean baseline, so these results are unresolved rather than known pre-existing failures. See [the run record](evidence/kernel-integration/main-default-qemu-2026-10-19/README.md).

The 1.0 target is stable, usable completion of committed functionality. Rust is appropriate where shared mutable state, contention, ownership, cancellation, rollback or concurrency invariants benefit from clearer control; simple C dispatch, glue, byte-copy and established hot primitives may remain. No LOC ratio or C deletion count is an acceptance gate. Overall release blockers and scope remain in the [1.0 plan](v1.0.md).
