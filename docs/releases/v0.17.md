# v0.17 发布准备

内核身份更新为 `A20OS_VERSION=0.17`，Linux ABI 的兼容 release 为 `20.0.17`。
Native 系统信息、Linux `uname` 与 `/proc/version` 共用
`kernel/include/core/version.h`。本页记录候选版本范围；版本号更新不等同于已经创建
tag 或发布镜像。

## 收尾时的发布阻塞（2026-10-08）

源码基线 `09148720` 的 [完整 CI](https://github.com/fQwQf/A20OS/actions/runs/37790742690)
已通过，包括源码门禁、七架构内核构建、四架构构建及该工作流的运行回归。
同一基线的 [发布分支验证](https://github.com/fQwQf/A20OS/actions/runs/37791671317)
四架构发布构建通过，但 RISC-V `smoke-abi-linux` 在初次运行和一次失败任务复跑中
均未在 20 秒内取得 `SYSCALL_SMOKE: PASS`，日志只到 `SYSCALL_SMOKE: start`。
后续 VFS/MM 步骤未执行，不能记为通过；该超时尚未定位，不通过延长时间或跳过
门禁将其计为成功。分支触发没有发布 GitHub Release。

两个 XFCE 实例也仍未通过真实桌面验收，具体观察见
[桌面排查收尾](../distro/known-issues.md#本轮交互排查收尾)。本轮停止扩展排查，
保留失败证据及已验证的独立修复，不创建版本 tag；以上阻塞解决前本页仍是
候选版本准备记录。

## 相对 v0.16 的主要变化

- 内存：单记录映射模型，以及 fork/mprotect/COW 和映射生命周期修复。
- 调度：内核态抢占，以及 Park/yield/唤醒交错修复。
- 网络：普通单播 TCP/UDP 使用 lwIP owner-lane 锁；N1/N4 外部连接专项验收
  检查双向数据，并观察到跨 lane 重叠执行。共享协议控制路径仍保留全 lane 屏障。
- 虚拟化：RISC-V H 下 A20OS RAMFS guest 可启动到交互 shell，完成命令往返、
  退出及 host 控制台恢复。
- 平台与图形：x86 ACPI/PCI 支持完善，virtio-gpu virgl 像素回读及 Mesa attach
  增加验证路径。

上述专项验收及适用基线见
[开发恢复记录](../development-recovery-2026-10-08.md)。本版本不宣称任意 Linux
guest、guest SMP、完整 FEX 支持、网络吞吐提升或多机集群生产就绪；平台真机验证
仍以 [平台就绪度](../server-readiness.md) 的边界为准。

## 构建与发布修正

构建工具默认使用系统 `python3`（3.11+ 标准库），允许显式覆盖 `PYTHON`，不依赖
Conda。用户态增量构建的产物检查相对仓库根目录解析，避免在临时 checkout 中误判
产物不存在并重复构建。固定 `/bin` 布局的 sandbox 启动脚本现位于
`tools/run-nested-a20`；开发机启动仍使用 `tools/a20 run` 或 `make run`。

unmap 完成前清理陈旧索引持有的映射引用，最后的 backing 资源引用在 TLB
失效完成后释放，修复 Native VMOL 对象计数未恢复的问题。Native FILE 映射改为
直接传递已引用的 `vfile`，避免把对象指针误当作 fd；映射在 source handle 关闭后
仍保留自己的文件引用。相关 Native、Linux ABI 和 MM 运行回归见
[测试门禁记录](../testing-gates.md#native-门禁的架构覆盖现状2026-10-核实)。

普通自旋锁在尝试取锁前发布禁止抢占的计数，争用失败时恢复调用方原有深度，避免
已经持锁的任务仍被 IRQ 返回路径切走。计数发布时短暂关闭本地中断，使 CPU 槽
选择与递增之间不能发生任务迁移。确定性宿主测试覆盖两个窗口、嵌套及中断状态
恢复；机制说明见 [内核态抢占点](../process-scheduler.md#41-内核态抢占点config_kernel_preempt)。

页表 MCS 锁也从选择 CPU 本地节点池前开始禁止抢占，直到解锁并弹出节点，避免
任务切换或迁移使解锁访问错误的节点与嵌套深度。Linux `waitid()` 改为按 ABI
结构写入 `siginfo_t`，保留 64 位平台的 union 对齐；编译期断言同时检查 32 位布局，
运行回归覆盖 pidfd、`WNOWAIT`、退出状态及回收后的 `ECHILD`。
子进程等待还修复扫描到 park 注册之间的丢失唤醒窗口，以及僵尸 leader 仍有
活动线程时错误返回 `ECHILD` 的问题；最后一个成员退出会通知 leader 的父进程，
pidfd 也等待整个线程组完成。退出通知不再使用锁前的全局 waiter 计数快速路径，确保与等待注册在同一把锁下
相遇。运行回归显式控制 leader 与成员的退出顺序，
检查中途的 `WNOHANG`、pidfd 可读性、`WNOWAIT` 和最终回收。
线程组成员现在持有 leader 引用直到成员最终释放，防止 leader 先被回收后，
成员 unlink 访问 leader 内嵌链表字段；宿主 ASan 回归包含移除引用的 UAF 负控。

x86 内核态驱动模块与内核共用禁止 FP/SIMD 的编译约束，防止设备操作覆盖用户
寄存器。`make smoke-x86-fp-preserve` 在四核、独立 ext4 磁盘上检查写入、fsync
和读回前后的 XMM0 内容；构建同时检查 ET_REL 模块不含 FP/SIMD 指令，CI 的
x86 构建任务运行该回归并上传日志。
同一门禁还通过 raw fork 检查子进程继承 XMM0、XMM15、x87 控制字与 MXCSR；
旧实现会把子任务 FP 状态重置为默认值，现改为快照 syscall 时的 live 状态。
x86 用户态返回入口关闭中断，内核 IRQ 尾声恢复入口 FS base，另有多线程 TLS
回归检查线程身份和跨 yield/syscall 的 FS 稳定性。

XFCE 桌面的验收单独检查顶部面板、dock、终端命令输出及窗口交互，见
[桌面验收要求](../testing-gates.md#xfce-桌面验收)。串口 smoke 不能代替这些项目。

CI 上传内核 ELF 和 smoke 日志时显式包含 `.kernel-build` 隐藏目录，保持窄范围的
产物路径。发布工作流校验 tag 与内核版本一致；从分支手动触发时执行构建、签名与
运行验收，但不创建 GitHub Release。签名要求不变。具体历史失败原因见
[CI/CD 说明](../packaging/ci.md)。

发布前应在候选提交上完成：

```sh
make check
make host-tests
make smoke-native-contract
make smoke-abi-linux
make smoke-vfs-stress
make smoke-mm-stress
python3 tools/check-release-version.py v0.17
```

还需确认该提交的远端 CI 架构矩阵、运行门禁及发布构建通过，再创建注解 tag。
`python3 tools/check-release-version.py` 不带 tag 时只检查两种内核版本号配对，
不修改文件；传入 tag 时还会拒绝与内核身份不匹配的版本。
