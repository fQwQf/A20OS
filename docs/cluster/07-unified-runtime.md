# MCU 与服务器统一集群机制

本文是 2026-10-11 开始的实现依据。原实施轨道记录已删除；其中暂停等待人工仲裁的流程由本轮已授权的设计完善与连续实现替代。
实现状态及运行证据集中记录在 `../status/current/cluster-implementation-status.md`。

## 1. 统一的含义

所有节点共用身份、服务槽位、CL 帧、调用事务、错误码和能力协商。
传输驱动只处理链路地址与字节搬运，不能改变业务消息语义。
MCU、普通主机、服务器是资源预算，不是三个互不兼容的协议。
节点角色（工作节点、网关、调度器）与处理器架构独立。

STM32、树莓派、RISC-V 开发板/MCU、x86/ARM 服务器沿用同一公共接口。
当前公共 fabric 实现与逐平台证据见
[27-portable-domains.md](27-portable-domains.md)；缺少板级实现的平台明确列为
待实现，不能以同 ISA 的 QEMU 或编译测试代替该板的支持。

统一机制分为共享内存域内的原生 SMP 和域间的服务集群。用户要求的单内核
跨物理 MCU 采用共享 RAM 与硬件仲裁，复用服务器的任务/PID/调度器机制；
实现与硬件契约见 [25-native-shared-kernel.md](25-native-shared-kernel.md)。
Java 客户端目标见 [24-single-system-minecraft.md](24-single-system-minecraft.md)。
指令模拟与 QEMU 共享内核已有阶段性验证，x86_64 Java 客户端证据见
[共享客户端](61-shared-minecraft-client.md)；物理 MCU、混合硬件及其他平台客户端不得据此外推。
现有 CL 服务机制保留，用于不同共享内存域及异构 ISA 的互操作。
早期按“先完成功能”组织的里程碑不包含完整性能验收。面向 1.0，服务集群与共享内核
须完成现有目标、物理验证、故障恢复及功能/性能对照，统一纳入
[发布计划](../releases/v1.0.md) 的 V1-CLUSTER；不能将首个功能里程碑当成开发完成。

完整主机通过 Native channel 使用远程服务；NOMMU 叶子以静态缓冲和周期泵
执行同一服务协议。叶子可注册预置算子，主机可注册算子或进程服务。
作业调度按能力匹配任务，不能把 ELF 任务发送到仅支持预置算子的节点。

## 2. 分层契约

1. CL 编解码：显式小端字段、长度校验、CRC、TTL；保留既有 wire v0 金样，会话事务使用显式协商的 v1。
2. 链路适配：loopback / UDP / UART，共用有界周期泵与链路事件。
   泵必须在独立线程执行，不能被等待服务处理的 RX 分发阻塞。
3. 节点数据面：身份与路由、服务导出、事务相关、去重与回复缓存。
4. 控制面：成员存活、服务目录、能力发布、动态路由与重启恢复。
5. 作业面：统一算子任务、显式进程任务、分片、重派和树形归约。

每个驱动必须声明 MTU。超过链路预算的消息必须在发送前明确拒绝，或进入
双方协商过的重组机制；不能静默丢弃后永久等待。非可靠与可靠调用均有期限。
可靠传输的交付确认与业务执行成功分别报告，不能把 ACK 解释为任务成功。

## 3. 身份、重启与转发

128 位 node_id 为持久身份，短地址和 IPv4 地址仅为可变化的下一跳。
wire v0 的 32 位节点哈希只作索引：路由安装必须拒绝哈希冲突，而不是任选一个。
握手绑定节点 ID 与链路地址；未知来源不能仅凭伪造 src_hash 调用导出服务。
握手 nonce 表示当前启动/链路会话，在同一会话的 HELLO 重试中保持稳定；
重启后旧会话事务与去重缓存不能继续有效。nonce 必须由可靠熵或持久 epoch 提供。
节点 ID 配置必须可持久化；禁止所有 MCU 默认使用同一个演示 ID 部署。

只有设置 RELAY 能力的节点允许转发。转发检查 TTL，逐跳递减并重新计算 CRC，
保留原调用者、目标和事务号；跨 UDP/UART 网关不能改写业务事务身份。
HELLO 绑定邻接会话，CS/1 双向挑战绑定最终目的 epoch，并沿途探测最小 MTU；
来源启动变化、网关启动变化和叶子启动变化分别处理。来源去重不能因网关
重启而被清除。具体格式和验证见 [15-routed-sessions.md](15-routed-sessions.md)。
loopback 虚拟节点仍是测试身份，共享导出表，不作为独立节点规模证据。

CRC 仅检测传输损坏。v0 部署边界为受控网络或专用串口；不能把地址绑定当作
密码学认证。开放网络接入必须由经过认证的隧道或后续认证协议提供信任根。

## 4. 调用与资源纪律

事务键包含来源、会话和 txid；txid 0 保留，回绕必须跳过在途编号。
服务先预留去重/应答资源，再执行；重复请求重放原回复，不能重复执行。
该保证只覆盖缓存保留期与当前会话，不承诺断电后 exactly-once。
作业仍采用至少一次执行与 `(job_id, shard_id)` 结果去重。

MCU 最小预算允许单在途、单回复缓存、单帧消息；服务器通过预算扩大并发与
缓存，并协商分片。所有表、队列、重试次数和重组总字节数都有上限。
缓存满不能逐出仍可能重试的执行记录后再次执行同一任务。
故障、取消、资源耗尽都必须最终完成调用，不能留下无期限挂起。

内部工作线程属于集群核心，不属于发起 syscall 的用户进程。其退出不要求
用户调用 task_wait，也不继承用户的文件、信号处置或安全过滤器。停止连接
后代理、重试缓冲、工作线程与内核栈都须回收；运行资源统计和任务生命周期
统计分别验证，不能用其中一个代替另一个。

### 容量与进展

背压沿“业务 channel → 有界在途窗口 → 传输 RX → 服务接收队列”传播；
每层有自己的容量与接纳结果。SEND 的本地提交、远端队列接纳和业务持久
处理是三个不同阶段，不能用前一阶段的计数代替后一阶段。

主机的 adapter poll 与 RX 分发由不同 owner 推进。共同 64 项 RX ring 在
32 项高水位暂停主动拉取，降至 31 项唤醒；直接 RX 提交仍是非阻塞操作。
每个 adapter 连续 100 ms 未轮询时获得一次有界轮询机会，避免拥塞无限
推迟控制 I/O，正常空闲等待仍最多 1 ms。这是调度机会的预算，不是心跳
帧送达的硬实时保证；adapter 自身仍须遵守字节/帧工作预算。具体实现和
负载证据见 [04-transports.md](04-transports.md)。

静态 leaf 用固定缓冲、单事务缓存和周期泵表达相同的有界接纳合同。业务
回调必须有界且不能重入协议泵；资源满时返回明确拒绝，重试保留原事务键。
主机通过 park token 等待空间，leaf 通过下次周期泵继续推进，不要求 MCU
为此引入堆、主机线程或相同大小的队列。

接纳失败按原因观测。ring 满与分配失败都是 RX_DROPS 的子集；没有物理
next-hop 的诊断计数不能增加 DOWN 链路数量。快照只保证各子系统内一致，
不能把不同时间的队列、链路和业务计数当作全局原子截面。验收同时核对
业务编号、最终送达、在途/重组回收与失败时快照。

## 5. 控制面和作业面

clusterd 持有成员和服务目录，管理 node_id、会话、能力及有效期。
探测失败先 suspect，再 dead；间接探测不能产生永久复活的旧 incarnation。
守护进程重启必须可重新取得当前内核身份与路由，不能要求重置数据面。
`service://any/name` 只选择存活且能力兼容的服务。

统一工作请求携带 job_id、shard_id、任务种类、算子/服务 ID、期限与输入。
叶子实现算子回调，主机 agent 也实现相同算子协议；主机额外支持进程任务。
重派只适用于明确允许重试的任务；归约结果按分片去重。结果可为有界字节串，
不局限于 u64；协调器只封装已提交的子结果，业务归约交给能力匹配的 agent。
所有节点共用 WORD_MAP/WORD_MERGE/CONCAT，实现细节见 18 文档。
树形归约限制每个聚合节点的扇入，节点退出时重新指派相关子树。
v0 根调度器故障时作业失败；持久化作业恢复属于独立能力，不能宣称已有。

## 6. 验收门槛

| 门槛 | 必须具备的证据 |
|---|---|
| G1 基础数据面 | 真实双内核 UDP CALL/REPLY、UART 头叶对接、轮询进展、TTL/冲突拒绝 |
| G2 可靠事务 | 丢请求/丢回复/重复/乱序/超时/断链/重启、资源满、txid 回绕 |
| G3 统一服务 | 同一算子客户端分别调用 MCU 与服务器，结果一致、能力拒绝明确 |
| G4 动态集群 | 多节点成员变更、服务 any 解析、控制面重启时数据面保持工作 |
| G5 分布式作业 | 服务器与 MCU 混合集群、分片重派、重复结果、树形归约 |
| G6 硬化 | 有界模糊测试、持续负载、资源统计、资源档构建与可复现性能记录 |

主机模拟测试、QEMU 独立内核和物理 MCU 测试分别列出。
没有硬件实测时只能声明协议仿真与固件构建通过。
任一验收项缺失时保留为未完成，不以改小设计范围代替实现。

1.0 对“当前 owner/会话/启动内至多执行一次”和“跨重启不重放、不自动迁移”
的边界决定见 [62-release-scope.md](62-release-scope.md)。该文档明确排除
跨重启 exactly-once 与运行中进程自动迁移，避免把失败关闭的 `EXPIRED`
语义误读为透明故障转移。
