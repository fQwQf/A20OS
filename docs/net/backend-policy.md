# 原版 lwIP、FreeBSD 与 A20OS 原生能力

2026-10-29 决策：停止把现有 lwIP 分叉作为长期架构。引入未修改上游的独立候选后端，
验收后替换已有 lwIP；FreeBSD 与可能的 A20OS 原生栈也是独立后端。旧分叉保留作迁移
参照和缺陷修复，不继续向其中添加 lane、TCP 或分配器层面的架构扩展。

## 为什么收敛魔改

lwIP raw API 建立在串行核心访问约束上。NO_SYS 模式不能让多个上下文同时访问
核心，OS 模式采用 tcpip_thread/core locking，而非任意拆分协议内部结构到多个核。
参考 [上游并发说明](https://www.nongnu.org/lwip/2_1_x/multithreading.html) 和
[NO_SYS 约束](https://www.nongnu.org/lwip/2_0_x/group__lwip__opts__nosys.html)。

现有分叉修改 PCB 布局/链表、lane 桶、定时器、内存池和拥塞控制；socket 桥又读取
这些字段。UDP connect 漏掉 wildcard 桶、重复登记形成自环，已被真实 Linux ELF
复现。这是偏离上游执行模型的维护成本，不能仅靠增加锁或资源容量解决。
小而明确的上游缺陷修复仍然合理，应有回归、来源和回传记录；深度分叉却长期当作
普通 lwIP 依赖，会同时失去上游可升级性和自研栈的清晰所有权。

## 能力归属

| 能力 | 长期所有者 | 约束 |
|---|---|---|
| socket ABI、fd、权限、等待与错误发布 | A20OS socket 前端 | 不暴露 PCB/mbuf；每个 socket 使用其网络域后端 |
| 接口身份、地址、FIB/策略、过滤/NAT 策略、追踪 | A20OS 公共控制与策略层 | 单一事实来源；后端执行副本需同步及失效事务 |
| DMA、NIC 队列与卸载、收发完成 | A20OS 设备与包 I/O 层 | 明确所有权、背压、批量预算和释放上下文 |
| TCP 状态机、重传、拥塞控制、协议缓冲与分配器 | 各协议栈后端 | lwIP 使用上游模型，FreeBSD 使用自身模型，不拼接跨栈 TCP 核心 |
| ARP/ND、分片重组、ICMP/PMTU 等协议执行 | 域内指定的协议实现 | 一个状态只有一个所有者，不独立维护两套协议状态 |
| DHCP/DNS/RA 等管理服务 | 用户态 Linux 程序 | 使用真实 socket 能力，不足之处明确报错 |

NAT/转发需要重组与 ICMP 差错翻译时，必须把执行顺序纳入后端契约，不能在
Ethernet 层只改第一片的端口，也不能放两套互不关联的邻居/重组表。
公共层持有策略，不等于公共层接管全部协议状态。

## 原版 lwIP 接入规则

`kernel/external/lwip-upstream` 是独立 submodule，固定发布标签
`STABLE-2_2_1_RELEASE` 的提交 `77dcd25a72509eb83f72b033d219b1d40cd8eb95`。
这是候选基线，不声称覆盖所有最新开发提交。上游目录不写入 A20OS 更改；port、hook、
`lwipopts.h` 和适配代码放在第一方后端目录。可以使用上游支持的
[hook](https://www.nongnu.org/lwip/2_1_x/group__lwip__opts__hooks.html)，不能靠同名
头文件偷偷替换内部结构以维持旧 ABI。

当前 `NET_STACK=lwip` 仍指分叉；`NET_STACK=lwip-upstream` 明确拒绝构建，直到独立
适配器可运行。获取源码不等于接入成功，不能默认回退后冒充原版。候选首先采用
每域串行协议执行，SMP 仍用于应用与 I/O，不宣称单域能并行执行多个 TCP 核心。
多域独立实例需先隔离上游全局状态，不能复制一把锁就宣称支持。

旧 CUBIC、wnd_limit、PCB lane、per-lane 池不搬入原版核心。原版不具备的选项明确
返回不支持；需要这些能力的场景选择其他后端，或者独立实现原生栈。切换后端不能
悄悄改变已支持的系统 ABI，必须有能力说明和对应验收。

## 原生自研栈的范围

自研不是回收所有魔改的容器。可以从有明确需求的路由数据面开始，但必须定义与
TCP endpoint 后端的域边界、流量归属和包转移。完整 TCP 自研需独立承担状态机、
安全、互操作、拥塞控制和维护成本，在成熟后端能满足需求时不提前承担。
Rust 优先用于有界状态、解析和队列所有权；FFI/DMA 的释放责任仍需明确并验证。

## 迁移顺序

1. 冻结旧分叉及功能、性能、失败样本；公共层不再新增私有字段依赖。
2. 隔离 INET 私有状态，建立有实际调用者的 socket、包 I/O、控制和能力契约。
3. 接入原版 lwIP，以同一 Linux ELF、相同 NIC/链路复跑 ABI、NAT、转发和服务。
4. 接入 FreeBSD，比较正确性、吞吐、p99、CPU/字节、连接规模与内存成本。
5. 验收后决定各场景默认后端并删除旧分叉，不提前选择服务器默认。

当前第2—4项尚未完成，分片 NAT、ICMP 差错/PMTU 与生产软路由整体验收也未完成。
