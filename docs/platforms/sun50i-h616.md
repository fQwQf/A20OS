# Allwinner H616 / H618（Orange Pi Zero 2、Zero 3、Zero 2W）

`ARCH=aarch64 BOARD=sun50i-h616`

**本仓库所有 ARM 板中最干净的启动链。** SPL 由 U-Boot 源码构建，BL31 是 TF-A 的 `sun50i_h616` 平台，
两者都在 mainline——链中没有任何构建无法复现的厂商 blob。对比 Rockchip（rkbin DDR 训练 blob）、
Amlogic（签名 FIP）、Raspberry Pi 5（根本没有 mainline U-Boot 目标）。板价约 18–35 美元，视变体与内存而定。

**只验证到构建。未在硬件上运行。** 该构建结论现在由 `make check-arm-board-builds` 在每次提交上复现，
因此这块板不会悄悄编译不过。

## 硬件事实

来自上游 Linux `551c722f40809618230001baccf219193e22fc5a` 的
`arch/arm64/boot/dts/allwinner/sun50i-h616.dtsi` 与三份 `sun50i-h618-orangepi-*.dts`：

| 项 | 取值 |
|---|---|
| SoC | Allwinner H616 / H618，4× Cortex-A53 |
| GIC | `interrupt-controller@3021000`，`"arm,gic-400"`——**GICv2** |
| UART0 | `serial@5000000`，0x400 字节，`GIC_SPI 0` → **IRQ 32**，`"snps,dw-apb-uart"` |
| 以太网 | `ethernet@5020000`（emac0），0x10000，`GIC_SPI 14` → IRQ 46，`"allwinner,sun50i-h616-emac0"` |
| SD | `mmc@4020000`，0x1000，`GIC_SPI 35` → IRQ 67，`"allwinner,sun50i-h616-mmc"` |
| DRAM | 0x40000000（这些板级 DTS 都没有 memory 节点） |
| 定时器 | DZI 24 MHz |

GIC 的 SPI 号 = 32 + DT 里的值；`sun50i_h616_platform.h` 已经做过换算。

其中两项是这块板便宜的原因。`"snps,dw-apb-uart"` 是 16550，各架构的 `console.h` 都已经声明。
`"arm,gic-400"` 是 GICv2，正是 aarch64 移植已经驱动的 `GICD_BASE`/`GICC_BASE` 那一对——不需要 GICv3
工作。DRAM 在 `0x40000000` 也正好是 aarch64 QEMU 默认指向的地址，因此内存窗口不需要改。

MAC 是 Synopsys DWMAC 变体（上游 `dwmac-sun8i.c`），与 `kernel/drivers/net/ls2k_gmac.c` 同属一个 IP
家族。这是这块板值得做的主要原因。

## 启动链

```text
Allwinner boot ROM  →  U-Boot SPL（源码构建）  →  TF-A BL31（mainline）  →  U-Boot  →  kernel
```

mainline U-Boot 有 `orangepi_zero2_defconfig`、`orangepi_zero3_defconfig` 与 `orangepi_zero2w_defconfig`。
TF-A 暴露 PSCI，正是 aarch64 移植已经在用的东西。

## 本移植的范围

完成：RAM、控制台 UART、GICv2、PSCI `poweroff`/`reboot`。

刻意缺席：

- **存储。** `allwinner,sun50i-h616-mmc` 是 Allwinner 自己的控制器，上游由 `sunxi-mmc.c` 驱动。A20OS 的
  `dw_sdio.c` 面向较老的 DesignWare SDIO/MMC 寄存器布局，而且没有通用 MMC 核心可供新的 host 插入。
  这是从卡启动的拦路石，也是 SophGo 移植止步于同一位置的原因——但更糟，因为 DWCMSH 至少还属于
  A20OS 有驱动的那一族。
- **以太网。** DWMAC，所以 `ls2k_gmac.c` 是起点，但它需要先有一套 Allwinner CCU 的时钟与复位序列，而该
  序列还没有推出来。
- **SMP。** `.smp` 为 `NULL`。四个核确实存在；这个 bootloader 对外发布其中哪几个尚未在硬件上核对；
  `porting-guide.md` 要求 `.smp` 保持 NULL，而不是携带一个编造的 ops 表。

## 部署

部署工具是 `tools/a20`。这里没有 make 命令，这是刻意的：本板没有块驱动，所以没有卡可写，也没有东西让
`dd` 去写镜像。产物是内核，加上把内核交给板上已有启动链的那几条命令。

### 你会得到什么

```sh
tools/a20 package sun50i-h616
```

写出 `build/sun50i-h616/handoff/`：`kernel.bin`、在 U-Boot 提示符下逐行执行的 `uboot.cmd`，以及携带同样
说明的 `README.md`。

装载地址**不**写在本文件或实例里。`a20 package` 从刚构建出的内核的第一个 `PT_LOAD` 头里读出它，因此链接
脚本会重定位镜像的板子不会在这里留下过期地址。

刻意不提供 device tree：U-Boot 在 `a1` 里传入它自己的板级 DTB，而内核是按"被告知布局"而不是"自己读取
布局"来构建的。

### 把它弄到板上

1. 按板子文档说明的方式启动。这条链**无 blob**，这正是选它的主要理由：H616 的 SPL 与 U-Boot 都能从
   源码构建，任何位置都没有厂商签名的 blob。把它们留在 TF 卡上。
2. 打断 U-Boot 的自动启动。
3. 从 TF 卡读内核：

   ```text
   mmc dev 0
   mmc read <loadaddr> 0x408000 0x8000
   ```

   `<loadaddr>` 是 `uboot.cmd` 打印的地址。后面两个数字是 FAT 分区起始与一个宽松的长度；请在板上用
   `mmc info` 核对两者，因为它们是起点而不是实测值。
4. 启动内核：

   ```text
   booti <loadaddr> - <loadaddr>
   ```

   中间的 `-` 是 device tree 指针，留空是因为 U-Boot 自己会在 `a1` 里传入它自己的板级 DTB。

### 验证

```sh
tools/a20 deploy sun50i-h616     # 构建、打包、打印命令，然后检查
tools/a20 console sun50i-h616    # 只观察并检查一块已在运行的板子
```

控制台是 `/dev/ttyUSB0`，115200。若适配器枚举成别的节点，改掉它——插拔前后各执行一次 `ls /dev/ttyUSB*`。

**在这个架构上，唯一的启动证据是 `System ready`。** 没有 `[FDT]` 行：只有 riscv64 与 loongarch 解析
device tree，aarch64 移植没有基于 DT 的 RAM 收窄，因此 `console_check` 只等这一个字符串。`System ready`
由 `kernel/main.c` 打印，意味着内核进入了用户态。

### 装载地址是第一个要查的东西

`KERNEL_ENTRY` 是编译期常量。H616 的 SPL 装载在 `0x40000000`，而 U-Boot 的 `loadaddr` 决定内核实际落在
哪里。两者不一致时，内核会跳到一个它并非为此链接的地址，板子在第一次 `printf` 之前就挂住。

### 如果启动不了

按实际最先出问题的顺序排列。

1. **控制台什么都没有。** UART 或 pinmux 错了。启动链释放 UART 时钟，所以静默通常意味着固件没跑。
2. **U-Boot banner 之后静默。** 装载地址，见上。这是本板第一个要核对的值。
3. **`mmc read` 什么也没读到。** 在板上用 `mmc info` 核对分区起始与长度；实例里的偏移是起点而不是实测值。

## 没有板子就无法定论的两件事

1. **`KERNEL_ENTRY` 是编译期常量且未验证。** H616 的 SPL 装载在 `0x40000000`；U-Boot 的 `loadaddr` 决定
   内核落在哪里。若板子在第一次 `printf` 之前挂住，这是第一个要查的值。
2. **DRAM 大小。** 没有任何板级 DTS 声明 memory 节点——布局由 U-Boot 传入——而 aarch64 移植没有 riscv64
   的 `riscv64_memory_init()` 那种基于 DT 的 RAM 收窄。`PHYS_MEMORY_END = 0x80000000` 是一个 1 GiB 的
   *窗口*，不是实测值。2 GiB 的 Zero 3 需要把它调高，否则分配器会发出一个并不存在的页。

两者都记录在 `sun50i_h616_platform.h` 中真正影响行为的位置。

## 在宣称硬件验证之前

1. 构建，把 U-Boot 的装载地址与 `KERNEL_ENTRY` 对比，并确认真实 DRAM 大小与 `PHYS_MEMORY_END` 相符。
2. 启动并确认控制台 banner。Zero 2 与 Zero 3 把调试 UART 引到排针 8/9（uart0）；Zero 2W 用的是另一组
   排针——先确认你手上是哪块，再假设第一个引脚上是 115200。
3. 按 `porting-guide.md` 记录验收表。
