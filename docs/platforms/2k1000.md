# LS2K1000-DP-V10 硬件事实

移植代码在地址冲突时，应以厂商 DTB、运行中的厂商 Linux 以及厂商驱动的实际行为为准，而不是处理器手册。

## 目标与恢复基线

- 板级：LS2K1000-DP-V10
- CPU：Loongson-2K1001 / LA264
- 板载 RAM：1 GiB
- 固件：U-Boot 2022.04-v2.1.0-00583-g2ed41674
- 串口控制台：NS16550A，物理地址 `0x1fe20000`，115200 8N1
- A20OS RAM 装载地址：cached DMW 地址 `0x9000000002000000`
- 物理复位之后必须仍能启动未经改动的厂商 Linux 镜像。

不要执行 `saveenv`、`sf write` 或 `sf erase`，也不要覆盖 `/boot/uImage`。实验性 A20OS 镜像以新的 `/boot` 名字上传，并且只在 RAM 中执行。

## 已验证的内存窗口

- Cached RAM DMW：`0x9000000000000000 + 物理地址`
- Uncached MMIO DMW：`0x8000000000000000 + 物理地址`
- A20OS 分配器窗口：物理 `0x00200000..0x0b000000`
- 内核装载/入口物理地址：`0x02000000`
- 固件占用的内存在 1 GiB 上限之下就开始；在完整保留内存图被搞清楚之前，必须维持这个受限的分配器窗口。

## 中断控制器事实

下列取值来自本板恢复出的厂商 DTB（`compatible = "loongson,2k1000-icu"`）与运行中的厂商 Linux：

| 项 | 物理地址 / 取值 | 依据 |
| --- | --- | --- |
| LIOINTC 主寄存器基址 | `0x1fe01400` | 厂商 DTB `reg` |
| per-CPU pending 基址 | `0x1fe01040` | 厂商 DTB `reg` |
| CPU0 low/high pending | `0x1fe01040`、`0x1fe01048` | 厂商驱动反汇编 |
| CPU1 low/high pending | `0x1fe01140`、`0x1fe01148` | 厂商驱动反汇编 |
| CPU 父中断 | DT interrupt `3`，LoongArch HWI1 / `ESTAT.IS[3]` | 厂商 DTB 与实测路由 |
| UART0 的 LIOINTC 源 | `0` | 厂商 DTB 与 `/proc/interrupts` |
| GMAC0 源 | `12`、`13` | 厂商 DTB |
| GMAC1 源 | `14`、`15` | 厂商 DTB |
| AHCI 源 | `19` | 厂商 DTB 与 `/proc/interrupts` |

与厂商内核驱动核对过的寄存器布局：

| 功能 | Bank 0 | Bank 1 |
| --- | --- | --- |
| 32 个源的 route 字节 | `+0x00..+0x1f` | `+0x40..+0x5f` |
| Enable 状态 | `+0x24` | `+0x64` |
| Enable/set | `+0x28` | `+0x68` |
| Disable/clear | `+0x2c` | `+0x6c` |
| 极性 | `+0x30` | `+0x70` |
| 边沿/电平 | `+0x34` | `+0x74` |

实测的 UART0 route 字节为 `0x23`：bit `0x20` 选择 HWI1，低两位 `0x3` 选择两个核。由于 A20OS 目前只支持 CPU0，它的 UART0 route 取值是 `0x21`。处理器手册里的 `0x1fe11400` 与 `0x1fe11040` 与本板 DTB 及运行内核冲突，移植不使用这两个地址。

## GMAC 与 PHY 事实

| 项 | GMAC0 | GMAC1 |
| --- | --- | --- |
| 物理寄存器窗口 | `0x40040000..0x40047fff` | `0x40050000..0x40057fff` |
| Compatible | `snps,dwmac-3.70a`、`ls,ls-gmac` | 同上 |
| LIOINTC 源 | `12`、`13` | `14`、`15` |
| 接口模式 | RGMII | RGMII |
| PHY 地址 | `0` | `0` |

两个控制器都标识为带 user ID `0xd1` 与 Synopsys ID `0x37` 的 DWMAC1000。厂商 Linux 声明支持普通与增强/替代描述符，并使用 ring 模式。A20OS 读到的 GMAC0 PHY ID 是 `0x0000010a`，厂商 Linux 为它绑定匹配的 Motorcomm YT85xx 驱动。不插网线时，厂商 Linux 让两个接口在管理面上保持 up，但报 `NO-CARRIER`、速率/双工未知、`Link detected: no`。A20OS 必须把它当作"接口已被发现但 carrier down"，而不是探测失败。

当前实现使用控制器的 16 字节基本 ring 描述符模式，两次轮询 PHY BMSR 以照顾其锁存低电平的 link 位，并保持两个 DMA 中断与 GMAC 的 LIOINTC 源均关闭。它在读取 DMA 归属之前以及归还归属之前做 cache 维护。无网线探测与 link-down 集成已在真板验证；描述符数据传输尚未验证。

## AHCI 与 SATA 事实

| 项 | 取值 | 依据 |
| --- | --- | --- |
| AHCI 寄存器窗口 | 物理 `0x400e0000..0x400effff` | 厂商 DTB/Linux |
| LIOINTC 源 | `19` | 厂商 DTB 与 `/proc/interrupts` |
| 控制器版本 | AHCI `1.3` | U-Boot `scsi reset` |
| 实现端口 | 一个 SATA 端口 | U-Boot 控制器报告 |
| 磁盘容量 | `62,533,296` 个 512 字节扇区 | U-Boot 与厂商 Linux |
| Linux 分区 | MBR 类型 `0x83`，起始 `4,194,367`，长度 `58,338,929` | 厂商 Linux |
| 根文件系统 | ext4，4096 字节块 | 厂商 Linux |

A20OS 平台前端现在把这个 MMIO 窗口直接交给共享 AHCI 核心，不走 PCI 枚举，也不用 QEMU 的 ECAM 窗口。该路径目前是纯轮询：源 19 与控制器中断保持屏蔽。AHCI 的 command-list、receive-FIS、command-table 与传输缓冲按规范要求的对齐分配，共享驱动把 host 与 per-port 寄存器基址分开保存。

`STORAGE_READ_ONLY=1` 是独立的构建档位。它的写封锁在 AHCI 命令层、MBR 分区包装层与 VFS 只读挂载三处共同生效。它识别合法的 DOS/MBR `0x83` 主分区，并把干净的 ext4 挂载到 `/extra`。若 ext4 带有不兼容的 `needs_recovery` 特性，A20OS 拒绝挂载并继续进入 RAM shell，不重放日志。对板载磁盘不启用任何 A20OS 写路径。

该实现在 QEMU 上用 `ich9-ahci` 测试盘验证：IDENTIFY、MBR 解析、干净 ext4 只读挂载、写打开被 `EROFS` 拒绝、整文件流式读取，以及 4 GiB 上下两侧的采样都通过。故意弄脏的 ext4 镜像被拒绝，测试盘在两次运行前后 SHA-256 不变。同一条轮询路径也通过了真板验证：板子报出 `SSTS=0x123`、`TFD=0x50`、`62,533,296` 扇区，选中 MBR `0x83` 分区，并把 ext4 只读挂载到 `/extra`。

## 当前验证状态

- 仅 RAM 的 shell、四级用户页表、TLB refill、进程 syscall、定时器中断、超时唤醒、idle 唤醒与单核抢占均已通过真板验证。
- cooperative 构建仍是轮询控制台的兜底路径。
- LIOINTC 支持从 UART0 源 0 开始；在每条设备路径各自通过针对性板级测试之前，其他源保持屏蔽。
- LS2K1000 的 AHCI 平台/轮询路径、MBR 分区包装、ext4 只读挂载与大文件读取已通过 QEMU 与真板验证。AHCI 源 19 保持屏蔽，存储写入仍不支持。
- PCI 配置、GMAC 数据传输与 SMP 仍未验证。
- GMAC 路径把 carrier-down 当作非致命状态并暴露给 lwIP；该无网线路径已通过真板验证。link-up、描述符数据传输、ping 与 socket 流量仍需接上网线。
- UART0 源 0 的投递、屏蔽/确认/重新使能、有界分派以及与本地定时器在 CPU0 上的共存，已通过真板验证（含物理复位后仍能启动未经改动的厂商 Linux）。
- 一次主历史重写之后，LS2K1000 移植已重放到新的 main 上，定时器/UART 工作重新验证通过；这构成当前的真板验证基线。
